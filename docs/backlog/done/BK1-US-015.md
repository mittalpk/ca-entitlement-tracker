# BK1-US-015 — Five entitlement formulas as Switch-routed Code branches

**Workflow ID:** BK1
**Phase:** 3 — Core Build (Alpha)
**Status:** NOT STARTED
**Story points:** XL

---

**As a** Corporate Actions Operations Team member,
**I want** the five entitlement formulas (DVCA, DVSE, SPLF, RHTS, TEND/CHOS) implemented as separate Switch-routed Code node branches with named-constant parameters,
**so that** each event type is calculated correctly and formula parameters are auditable, not scattered as inline literals (NFR-006).

**Traces to:** FR-006, FR-007, FR-008, FR-009, FR-010, FR-011 (`requirements.md` §4.3, §6.5)

**Acceptance criteria:**
- Given `eventType=DVCA`, `position=14999`, `grossRatePerShare=0.42`, When calculated, Then `entitlementCash=6299.58` (half-up rounding, TC-001).
- Given `eventType=DVSE`, `position=153`, `stockDividendRatio=0.10`, `fractionalCashPrice=25.00`, When calculated, Then `entitlementShares=15` and `fractionalCash=7.50` (TC-002).
- Given `eventType=SPLF`, `splitRatio="3:1"`, `position=10000`, When calculated, Then `newPosition=30000`, `entitlementCash=0`, `entitlementShares=0` (TC-006).
- Given `eventType=RHTS`, `mandatoryVoluntaryFlag=VOLU`, When calculated, Then a `PENDING_ELECTION` record is produced, not an automatic credit (TC-003/AC-008).
- Given `eventType=TEND`, `optionDetails` with 3 options, When calculated, Then 3 `PENDING_ELECTION` records are produced with no automatic entitlement (TC-007).
- Given `position=0` for any event type, When calculated, Then entitlement is zero, logged, not skipped or errored (TC-005/AC-004).

**Definition of Ready:** `04-deterministic-logic-spec.md` pseudocode available; Lookup node built (BK1-US-014).

**Definition of Done:** All 5 branches built; each Code node has named constants (rounding rule, etc.) declared at the top per NFR-006; Switch node routes correctly on `eventType`.
