**As an** Asset Servicing Risk & Control reviewer,
**I want** the IF-node deadline gate to compute `daysToDeadline` and route into exactly one of four escalation tiers, with the `daysToDeadline = 0` boundary routing to BREACH (not URGENT),
**so that** the highest-risk failure mode (missed voluntary election) is never silently misclassified as merely urgent.

**Traces to:** FR-012, FR-013, FR-014, FR-015, FR-016 (`requirements.md` §4.4)

**Acceptance criteria:**
- Given `daysToDeadline > 10`, When routed, Then it lands in INFORMATIONAL (log only, no escalation).
- Given `3 ≤ daysToDeadline ≤ 10`, When routed, Then it lands in REMINDER (standard-channel notification).
- Given `0 < daysToDeadline < 3`, When routed, Then it lands in URGENT (separate high-priority channel).
- Given `daysToDeadline ≤ 0`, When routed, Then it lands in BREACH (incident-log entry, `incidentFlag=TRUE`) — explicitly verified for the `daysToDeadline = 0` boundary value, not just negative values.

**Definition of Ready:** Formula branches built (BK1-US-015) for RHTS/TEND/CHOS (only voluntary/choice events reach this gate).

**Definition of Done:** IF-node logic built; boundary values 11/10/3/2/1/0/-1 all manually verified against `05-test-plan-edge-matrix.md` §2 boundary table.
