**Workflow ID:** BK1
**Phase:** 1 — Discovery & Requirements Sign-off
**Status:** Done (retrospective record)

**As a** Data Governance Lead,
**I want** the data model, classification, retention, and erasure rules defined before any build work touches real or synthetic client data,
**so that** data-minimisation and retention obligations are designed in, not bolted on.

**Traces to:** NFR-004, GDPR-Art5-001, GDPR-Art17-001 (`requirements.md` §6.1, §6.4, §6.6)

**Acceptance criteria:**
- Given the position-book schema (§6.4), When compared against the audit-trail schema (§6.6), Then no field beyond `clientId` and position/entitlement data appears in either (no name, address, DOB, etc.).
- Given the data-category table (§6.1), When each category is checked, Then a retention period and erasure mechanism is stated for all five categories.

**Definition of Ready:** Position-book and audit-trail column lists drafted.

**Definition of Done:** §6.1, §6.4, §6.6 committed and cross-checked for extraneous PII — none found.
