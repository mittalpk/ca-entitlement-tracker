# BK1-US-013 — Webhook validation of MT564-shaped payload

**Workflow ID:** BK1
**Phase:** 3 — Core Build (Alpha)
**Status:** NOT STARTED
**Story points:** M

---

**As a** Corporate Actions Operations Team member,
**I want** the Webhook trigger to accept a valid MT564-shaped JSON payload and reject malformed/incomplete ones with a structured HTTP 400,
**so that** downstream nodes never process an event missing the fields the entitlement formulas depend on.

**Traces to:** FR-001, FR-002, FR-003 (`requirements.md` §4.1)

**Acceptance criteria:**
- Given a valid payload with `eventId`, `isin`, `eventType`, `mandatoryVoluntaryFlag`, `recordDate`, When posted to the Webhook, Then the workflow proceeds past validation.
- Given a payload missing `recordDate`, When posted, Then the workflow returns HTTP 400 with a structured error body and no downstream node executes (TC-008).
- Given `mandatoryVoluntaryFlag = "XXXX"`, When posted, Then the workflow rejects it as an unrecognised value.

**Definition of Ready:** n8n instance provisioned; Webhook secret header token configured (NFR-003).

**Definition of Done:** Webhook + Validation Code node built; TC-008 and the malformed-input matrix (`05-test-plan-edge-matrix.md` §6) pass manually at least once.

**Dependencies:** BK1-US-006, BK1-US-011
