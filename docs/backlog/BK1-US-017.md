# BK1-US-017 — Basic LLM Chain drafts notification from locked figures

**Workflow ID:** BK1
**Phase:** 3 — Core Build (Alpha)
**Status:** NOT STARTED
**Story points:** L

---

**As a** Compliance Officer,
**I want** the Basic LLM Chain node (never the Agent node) to draft notification text strictly from pre-computed, locked entitlement figures,
**so that** the LLM cannot recalculate, estimate, or alter any financial figure (BR-004), keeping the EU AI Act classification at Limited-risk.

**Traces to:** FR-017, FR-018, FR-019, FR-020 (`requirements.md` §4.5)

**Acceptance criteria:**
- Given a mandatory event's locked entitlement figures, When passed to the LLM Chain, Then the drafted notification states client ID, ISIN, event type, entitlement amount/quantity, and payment/settlement date, with every numeric value matching the locked input exactly.
- Given a voluntary event's `optionDetails`, When passed to the LLM Chain, Then the draft includes a plain-language explanation of each option and the default outcome if no election is received, using `optionDetails[].description` verbatim as input.
- Given the node palette, When inspected, Then the Agent node variant is confirmed absent from the workflow (FR-020/CON-002).

**Definition of Ready:** ADR-001 accepted; entitlement figures available as locked variables from formula branches (BK1-US-015) and deadline gate (BK1-US-016).

**Definition of Done:** LLM Chain node built with a sticky note documenting the no-Agent-node constraint (per `requirements.md` §8.3 AI governance node rule); at least one manual run confirms no unexpected numeric appears in output (DQ-011-style check).

**Dependencies:** BK1-US-015, BK1-US-016
